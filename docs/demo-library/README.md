# SignSure demo library — readiness manifest

Generated by `backend/tools/build_demo_library_manifest.py` from the live database. Do not hand-edit this file; re-run the generator instead.

Source captures live in `trainer/` and are never modified, renamed, or deleted by this pipeline. Each asset below was copied into an isolated upload folder under a clean import name and ingested through the normal Capture service functions (`create_job` + `run_ingest`), the same functions the `/api/v1/captures` endpoint uses.

**No sign-start/sign-end timestamps were supplied during import.** `app.ingest.rokoko.with_phase_bounds` marks any supplied timestamp as human-reviewed (`phase_source="authored-ui"`, `phase_reviewed=True`) and has no way to tell a script's number from a person's. Supplying our own auto-detected numbers through that path would have falsely labelled every clip as human-reviewed. Every clip below is therefore honestly marked `phase_reviewed=false`, using the pipeline's own automatic stroke detection (`app/ingest/segment.py`) as a QC proposal only.

| State | Meaning |
|---|---|
| `subtitle-video-plan-ready` | Reviewed phases exist; works for direct play *and* video-plan/subtitle composition. |
| `awaiting-phase-review` | Imported, canonical, plays directly today; blocked from video-plan/subtitle composition only, until a human reviews Start/Sign/End timestamps. |
| `awaiting-phase-review-blocks-direct-playback` | Imported, canonical, but the *detected* envelope itself fails the avatar's blend-quality gate (`POST .../track` returns 409) — bridging from rest enters the recording while it is still moving too fast. | `failed-or-missing` | Raw source, validation, or ingestion failed; nothing was registered. |

## Direct signs vs. subtitle aliases vs. fallback spelling

- All 23 required word glosses (`HELLO` … `AWAY`) are registered as single-word *candidate* patterns in `backend/app/services/isl_patterns.json` (registry version 2), so a subtitle unit whose text is exactly that word resolves to that one gloss via `translate_service.interpret` / `video_plan_service.resolve_caption`.
- **ADVICE** is documented here as a subtitle alias of **ADVISE**: the `advise` pattern's `forms` list is `["advise", "advice"]`, both mapping to the single gloss `ADVISE`. There is exactly one `SignClip` row for `ADVISE` — no duplicate motion asset was created.
- **BEND** is *not* a direct sign and has no gloss or pattern of its own. It is only reachable as an extension fallback plan: the literal caption-policy fallback in `video_plan_service.resolve_caption` (and the live-speech equivalent in `live_translate_service.interpret_live`) spells any word with no pattern/alias match using per-letter canonical alphabet clips, so `bend` would resolve to the sign sequence **B → E → N → D** using the four alphabet clips imported here. This was verified at the word-resolution layer (`resolve_caption("bend")` returns four fingerspelled items in that order) but, like every other asset in this library, is still blocked from actually playing through a video plan until those four letter clips get human phase review (see the queue above).
